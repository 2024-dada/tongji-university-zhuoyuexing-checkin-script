# 卓越星统一助手

勾选弘文、明德、矢志、求索、力行中的任意组合，或点击“全选”。

解压后双击外层“启动卓越星助手.cmd”。首次在主界面点“填写 / 修改 API key”，粘贴自己的密钥并点“确定”；主界面显示已配置后即可使用。“使用说明”和“查看打卡记录”也在主界面，不需要找文件或修改配置。企业微信先登录卓越星并打开底部加号后的五种星列表；Edge 登录后停在五项打卡列表，勾选“在 Edge 打卡”。矢志也从五项列表进入。勾选星项后点击“继续运行”。全部模式先完成企业微信四种星，再进入 Edge 矢志流程。

## 记录与列表查重

程序文件/打卡记录/ 中每种星各有一个“星名打卡记录.txt”。每次选择前重新读取，列表中按名称关键词识别已用对象，命中后不点进去、不生成材料。常规四星沿用剩余次数调度；矢志沿用网站可打卡状态与定位范围处理。系统新提示“已打卡”也会保存，以后在列表直接跳过。

首次运行本机升级会导入旧总 TXT 和旧矢志 TXT，原文件保留。迁移标识存在后不会再次导入，避免恢复已主动移除的记录。打卡前没有记录、系统列表又不显示历史状态的对象，无法凭空知道以前是否打过；首次系统提示后会记住。不要删除记录目录，否则会失去本地查重依据。

## 续跑记忆

程序把“上一次停在哪个对象”记在 程序文件/打卡记录/续跑记忆.json（五种星各自一条，矢志按“附近地标”列表单独一条）。下次运行先跳到这个位置，断点之前的条目不再逐条检查，从断点之后继续查找未使用对象，省去每天从头滚完整个列表。主界面和“更多设置”里会显示各星上次停在哪里。

续跑记忆只决定“从哪里开始找”，判重仍只看各星 TXT：跳过已记录对象、生成材料、提交这几步都不变。如果列表顶部新增了任务、或想重新扫一遍全部条目，点“更多设置 → 清除续跑记忆（从头开始）”。断点之后已经没有未做条目时，程序扫到列表末尾会重置记忆，下一次从列表开头查找，所以后来插在顶部的任务仍然会被发现。记忆里的对象已从列表消失时，程序会自动清除这条记忆并回到列表开头按常规查重继续，不会静默跳过整份列表。该文件损坏或删除都只影响起点，不影响已打卡记录。

## 给维护者

app.py 为统一窗口与顺序调度；checkin/batch.py 定义四星批次与五种菜单；checkin/engine.py 处理常规四星；checkin/shizhi.py 处理矢志；storage.py 的 ThemeHistory 管理五份权威 TXT，History 保留旧格式兼容；resume.py 只记录各列表的续跑起点。不要将矢志强塞进四星表单流程。修改查重必须验证列表按钮点击前跳过，并核对外部 TXT 更新和重启后行为；修改续跑记忆必须验证“断点之前的条目没有被点击”，且记忆损坏或对象消失时能回退到从头查重。

分享包含 Python 运行时、公共源码、测试和驱动；五份记录为空，密钥不打包。收件人首次在设置填写自己的 DeepSeek API key。源代码中的 tests 可使用附带 runtime/python.exe -m unittest discover -s tests 运行。构建入口为 tools/build_portable.py。
